Best Practices: Building in CMP and Mark

How to design agents, workflows and content processes that stay reliable as you scale

1. How CMP and Mark work together

CMP manages the work: tasks, briefs, templates, approvals and publishing. Mark does the work: specialized agents handle focused steps, and workflow agents orchestrate them. Connect the two with a CMP external step that triggers a Mark workflow agent by webhook, then lets Mark mark the step complete.

→
WebhookCMP sends external_sub_step_started
→

→

2. Best practices in Mark

Specialized agents

  • ScopeIf you can describe the job with one verb (summarize, scan, translate), it is scoped well. Split multi-step agents into smaller ones.
  • PromptUse clear, direct language and a top-down sequence (collect inputs, then summarize, then produce output). Avoid pointing backward.
  • StructureUse headers, bold and lists to give the prompt a clear hierarchy.
  • VariablesDefine inputs in the Variables section and reference them as [[VARIABLE_NAME]].
  • ToolsAgents only use tools you add. Name each tool in backticks and say when and how to use it.
  • ReasoningSet the Inference Level to match the task: higher levels reason more deeply but take longer.

Workflow agents

  • ModularKeep each agent to one task or decision point.
  • LogicPut branching and repetition in workflow steps (conditions, loops), not inside one agent.
  • ConditionsUse precise criteria. Add an Else path for anything unexpected.
  • LoopsRun iterations in parallel for independent items. Turn parallel off when iterations share a resource or order matters. Up to three nested loops.
  • Code stepsUse them to reshape data between steps. They have no LLM or network access.
  • TriggersChoose the trigger that fits the context (chat, webhook, schedule, email).

Design, test and monitor

StageWhat to do
DesignAsk Mark to draft or edit the agent in chat. It flags ambiguous wording, validates configuration, suggests missing tools and generates test samples before you go live.
TestUse Test run. Run the agent at least five times with different inputs and check the results are consistent. Workflow agents with a chat trigger can be tested before deployment; webhook, schedule and email triggers cannot.
LaunchAdd a clear description and note any input requirements or limits so others know how to use it.
MonitorReview execution logs. The Quality tab scores each run against your criteria and flags runs that deviate from normal behavior.
IterateRefine from feedback. Workflow agents keep version history, so you can compare runs and restore an earlier version.

3. Best practices in CMP

Workflows and governance

  • HybridCombine flexible steps with locked governance steps (compliance, legal). Use Step Lock, Assignee Lock and Asset Lock where control matters.
  • PublishingOnly tick Publish/Share on the final workflow step.
  • ReuseCheck for an existing workflow before creating a new one, so tasks follow established processes.

Tasks, briefs and templates

  • TemplatesUse task templates for work that repeats and form templates to give requests structure.
  • BriefsUse brief templates for campaigns and tasks so every brief captures the same essentials.
  • DependenciesLink related tasks so due dates shift automatically when plans change.
  • ContextStore brand guidance, personas and KPIs once as reusable instructions or skills, so every agent and brief starts from the same source of truth.
  • CheckersGive each review agent (brand, legal, compliance, accessibility) its own rulebook. Have it flag issues and suggest fixes in the task, and keep a person as the final approver.

You do not need every use case on day one. Prove one, then build on it.

5. Putting them together: AI-assisted CMP workflow

  1. Design the CMP workflow first. Mark the steps that AI will handle as external steps, and name each external system clearly (the name is case-sensitive and drives routing).
  2. Build a Mark workflow agent with a webhook trigger and an External Step Router agent that sends each external system name to the right branch.
  3. Build one specialized agent per job (for example brief enhancement, compliance check, translation), each with defined inputs and tools.
  4. Finish each branch by calling back to CMP with the update_task_substep tool, so the step completes and the task advances.
  5. Create the CMP webhook for external_sub_step_started. The secret in CMP must exactly match the auth key in Mark.
  6. Test end to end with a real task, then check Mark's workflow logs and confirm the step completed in CMP.
  7. Add safeguards: an Else or UNKNOWN branch, failure handling, and a notification with send_email.
  8. Keep a human review step in CMP before anything is published.

6. Troubleshooting: step does not advance

Check that (1) update_task_substep is enabled on the agent, (2) the task_id_or_url variable flows through the workflow, (3) Mark is connected to the correct CMP instance, (4) the external system name matches exactly, and (5) the router has a condition for that system.
